# VS No Vibe

**No vibe, just hands.** Никакого вайба — только руки: переписывай сгенерированный ИИ код вручную, файл за файлом, открыв эталон рядом в режиме «только для чтения».

ИИ-агенты пишут код быстро. Слишком быстро. Если хочется, чтобы кодовая база была по-настоящему *твоей* — понятной и поддерживаемой без вопросов к модели «а что делает этот код?» — работает старый приём: copywork. Читаешь эталон и набираешь каждый символ руками — и код становится твоим.

VS No Vibe берёт на себя скучную часть этого процесса в VS Code.

## Как это работает

1. Агент нагенерировал файлов (скажем, в `src/`). ПКМ по этой папке в Проводнике → **VS No Vibe: Start Rewriting Folder…**
2. Расширение сканирует её (пропуская `node_modules`, бинарники, lockfile'ы, dotfile'ы и слишком большие файлы) и создаёт рядом зеркальную папку — `src.handwritten/`, заполненную **скелетами**: пустыми строками в точной раскладке каждого файла.
3. Открывается diff: **слева твой файл, справа эталон от ИИ (только для чтения)**.
4. Печатаешь. Статус-бар показывает `✍ 42% · 3/12` — процент переписанных строк эталона и число готовых файлов. Настоящая вставка блокируется, автодополнение работает.
5. Когда копия совпала с эталоном, файл помечается готовым, а `Ctrl+Alt+N` переносит к следующему.

Твои оригиналы не изменяются — они служат только эталоном. Переписанные файлы — обычные файлы на диске.

## Команды

| Команда | Клавиши | Описание |
| --- | --- | --- |
| `VS No Vibe: Start Rewriting Folder…` | — | Выбрать папку, создать скелеты-зеркала, открыть первый файл |
| `VS No Vibe: Start Rewriting File…` | — | То же для одного файла |
| `VS No Vibe: Next File` | `Ctrl+Alt+N` | Следующий незавершённый файл очереди |
| `VS No Vibe: Previous File` | `Ctrl+Alt+P` | На один файл назад |
| `VS No Vibe: Choose File…` | `Ctrl+Alt+O` | Вся очередь списком (✓ готово, ● текущий) |
| `VS No Vibe: Mark Current File as Done` | — | Когда закончил файл по-своему |
| `VS No Vibe: End Session` | — | Завершить сессию (переписанные файлы остаются на диске) |
| `VS No Vibe: Apply Calm Diff Colors` | — | Применить спокойную палитру diff (тонкие полоски в gutter) к настройкам |

Все команды также доступны в контекстном меню файлов и папок в Проводнике.

## Настройки

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `vsnovibe.targetFolderSuffix` | `.handwritten` | Суффикс зеркальной папки. Если исходная папка — корень workspace, внутри неё создаётся `handwritten/`. |
| `vsnovibe.exclude` | `node_modules`, `.git`, `dist`, … | Имена файлов и папок, пропускаемых при сканировании. Dotfile'ы, бинарники, lockfile'ы и минифицированные файлы пропускаются всегда. |
| `vsnovibe.typeableReference` | `true` | Эталон показывается «печатаемым»: длинные тире `—` → `-`, фигурные кавычки → `'`/`"`, неразрывные пробелы → обычные. Что видишь — то и можешь набрать, и строка зеленеет, когда дописана. |
| `vsnovibe.skeletonLines` | `true` | Копия создаётся не пустой, а с тем же числом пустых строк, что у эталона. Панели diff одной длины: нет штрихованной зоны под текстом, курсор на Enter не прыгает. |
| `vsnovibe.maxExtraLines` | `5` | На сколько строк копия может вырасти относительно эталона. Лишние пустые строки убираются автоматически ~0,4 с после паузы в наборе (строки с содержимым не трогаются). |
| `vsnovibe.calmDiffColors` | `ask` | Предложить спокойные цвета diff при первой сессии: `ask`, `apply` или `off`. |
| `vsnovibe.pasteBlock.enabled` | `true` | Блокировать вставку в переписываемые файлы: откатываются вставки, совпадающие с буфером обмена. Автодополнение и сниппеты работают. |
| `vsnovibe.pasteBlock.minChars` | `8` | Минимальная длина одиночной вставки, которая сверяется с буфером обмена. |

## Полезно знать

- Панель эталона — **виртуальный документ только для чтения**: случайно испортить оригинал нельзя.
- **Слишком много красного и зелёного?** Расширение само предложит спокойные цвета при первой сессии (тонкие полоски в gutter + лёгкий оттенок изменённых символов), либо в любой момент — команда *VS No Vibe: Apply Calm Diff Colors*. Настройка `vsnovibe.calmDiffColors` (`ask`/`apply`/`off`); ваши собственные `diffEditor.*` кастомизации никогда не перезаписываются. Настроить вручную можно в пользовательском `settings.json` (*Preferences: Open User Settings (JSON)*):
  ```jsonc
  "workbench.colorCustomizations": {
    // заливку целых строк — выключить
    "diffEditor.insertedLineBackground": "#00000000",
    "diffEditor.removedLineBackground": "#00000000",
    // лёгкий оттенок внутри изменённых символов
    "diffEditor.insertedTextBackground": "#2EA04320",
    "diffEditor.removedTextBackground": "#F8514920",
    // тонкие полоски в gutter
    "diffEditorGutter.insertedLineBackground": "#2EA043",
    "diffEditorGutter.removedLineBackground": "#F85149"
  }
  ```
- **Штрихованная зона под текстом** — это внутренняя отрисовка diff-редактора VS Code «ниже конца файла» у более короткой стороны: клик туда пристёгивает курсор к концу документа (поэтому Enter «прыгал в самый низ»). Расширение не может её перекрасить, поэтому VS No Vibe убирает саму причину: при включённом `vsnovibe.skeletonLines` обе панели одной длины, и зоны просто нет.
- «Готово» ставится автоматически, когда файл совпал с эталоном построчно (строки сравниваются без пробелов по краям и с нормализацией тире и кавычек; пустые строки не в счёт), либо вручную через *Mark as Done* — если ты сознательно перестроил код.
- Прогресс — наибольшая общая подпоследовательность непустых строк: эталон против твоего файла. Файлы длиннее 5000 строк показывают `–`.
- Сессия переживает перезагрузку окна; переоткрыть diff можно через *Choose File…*.
- Уже существующие файлы зеркала с содержимым не перезаписываются никогда; совсем пустые копии при (пере)запуске сессии заполняются скелетом.

## Установка из исходников

Нужен Node.js 18+.

```bash
git clone <этот-репозиторий>
cd vsno-vibe
npm install
npm run package          # → dist/extension.js
npx @vscode/vsce package # → vsno-vibe-x.y.z.vsix
code --install-extension vsno-vibe-x.y.z.vsix
```

Для разработки: откройте папку в VS Code и нажмите `F5` (Extension Development Host).
Сквозной smoke-тест: `npm run smoke` — запускает расширение в чистом VS Code на тестовой папке (при первом запуске скачивает свежую сборку в `.vscode-test/`).

Работает в VS Code, Cursor, VSCodium и других совместимых редакторах.
